# Aspectra

**Aspect-aware customer feedback intelligence.** Aspectra reads customer reviews, finds what each
sentence is about (**price, quality, delivery, support**), scores the mood of each one
(positive, neutral, negative), and answers questions about recurring issues using only the reviews,
with review IDs as proof.

- **Live demo: https://aspectra-1.onrender.com
- **Evaluation report:** [EVALUATION.md](EVALUATION.md)
- **Demo video:** _add your video link here_

> The demo data is **synthetic** (generated by a script). No real customer data is used.

---

## What it does

| Feature | What you see |
|---|---|
| **CSV loading with checks** | Reads a CSV with `review_id` and `text` columns (`product` and `rating` are optional). It accepts commas or semicolons and Excel's Windows encoding, removes empty and duplicate reviews, and refuses files that aren't CSVs, with a clear message. |
| **Aspects and mood** | Each sentence is tagged with an aspect and a mood. A net score is shown per aspect (% positive − % negative). |
| **Dashboard** | Mentions per aspect, the positive / neutral / negative split, a 3D view where every dot is one mention, and the **top recurring complaints**, with similar wordings grouped together. |
| **Ask the reviews** | Ask questions in plain English, such as _"What do customers complain about with delivery?"_ or _"Do people like the price of the Coffee Maker?"_. The answer lists the most common points with the **review IDs that said them**. If no review covers the question, it says _"There is not enough evidence in the reviews to answer this question."_ and does not guess. |
| **Evidence explorer** | Every analysed sentence, which you can filter by aspect and mood. Click an ID to read the full review. |
| **Evaluation** | Precision, recall, F1, a mood confusion matrix and failure cases, computed live from hand-labelled sets. |
| **Upload your own CSV** | The whole page updates to analyse your file. |

## Results (sealed test set)

Scored on **49 hand-labelled review–aspect examples from 36 reviews** that were never used to tune the code:

| | Precision | Recall | F1 |
|---|---|---|---|
| Aspect detection (all) | 0.97 | 0.69 | **0.81** |

**Mood accuracy:** 0.76, measured on the 34 aspects that were found correctly.

The biggest weakness is **quality** (recall 0.32), because quality words that are not in the keyword list are missed.
The full breakdown, the confusion matrix, all 24 failure cases and the before/after history are in [EVALUATION.md](EVALUATION.md).

## How it works (architecture)

```
 reviews.csv / uploaded CSV
          │
          ▼
 1. Load & check      aspectra/load_data.py   pandas: required columns, empty + duplicate rows, encodings
          │
          ▼
 2. Split             aspectra/aspects.py     sentences, and at "but / though" (one opinion per piece)
          │
          ▼
 3. Find aspects      aspectra/aspects.py     keyword taxonomy for price / quality / delivery / support
          │
          ▼
 4. Score mood        aspectra/sentiment.py   VADER sentiment model + 36 shopping words → −1 … +1
          │
          ▼
 5. Answer & group    aspectra/qa.py          filter by aspect / mood / product, group similar
          │                                    sentences into recurring points, cite review IDs
          ▼
 FastAPI JSON API     aspectra/api.py         /api/summary  /api/ask  /api/reviews  /api/review/{id}
          │                                    /api/eval  /api/upload
          ▼
 Website              web/                    plain HTML, CSS and JavaScript + Three.js (3D view)
```

**Question answering is retrieval-based (extractive).** The app works out which aspect, mood and product
the question is about, keeps only the matching analysed sentences, and groups sentences that share
most of their meaningful words. Each answer is built only from those sentences, so it cannot invent anything.
No LLM is used to write answers.

## Why this model?

| Option | Why it was or wasn't used |
|---|---|
| **Keyword taxonomy + VADER (chosen)** | Free, runs on any laptop or free host in milliseconds, needs no GPU or API key, and every decision can be explained ("this word matched"). That matters for a small, honest MVP. |
| Fine-tuned transformer (e.g. a BERT-style ABSA model) | Would probably catch more quality mentions and sarcasm, but needs labelled training data, more memory than a free host gives, and is harder to explain. |
| LLM (e.g. a hosted chat model) | Flexible, but it costs money per call, needs an API key, can give different answers each run, and its labels can't be treated as ground truth. |

The evaluation shows where this choice hurts: unknown quality words and sarcasm (see [EVALUATION.md](EVALUATION.md), section 6).
The natural next step would be a small sentence-embedding model for aspect detection.

## Run it on your computer

You need **Python 3.10 or newer**.

```bash
# 1. Get the code and go into the folder
cd aspectra

# 2. Create and turn on a virtual environment
python -m venv venv
venv\Scripts\activate            # Windows
# source venv/bin/activate       # Mac / Linux

# 3. Install what it needs
pip install -r requirements.txt

# 4. Make the 400 demo reviews (always the same, seed 42)
python data/make_reviews.py

# 5. Start the app
uvicorn aspectra.api:app --reload
```

Open **http://127.0.0.1:8000**. The API documentation is at **http://127.0.0.1:8000/docs**.

**Run the tests and the evaluation:**

```bash
python -m pytest                          # 16 checks: loading, aspects, mood, API, sealed score
python -m eval.evaluate eval/exam.csv     # the sealed exam (F1 0.81)
```

## Deploy (Render, free)

1. Push this folder to a GitHub repository.
2. On [render.com](https://render.com), choose **New → Web Service** and pick the repository.
3. Use these settings:
   - **Build command:** `pip install -r requirements.txt && python data/make_reviews.py`
   - **Start command:** `uvicorn aspectra.api:app --host 0.0.0.0 --port $PORT`
   - **Instance type:** Free

The free tier sleeps when nobody uses it, so the first visit can take about a minute to wake up.

## Project structure

```

  load_data.py       read + check the CSV
  aspects.py         aspect keyword taxonomy and sentence splitting
  sentiment.py       VADER mood scoring with shopping words
```

## Data and rights

- **Demo reviews:** 400 synthetic reviews of 4 made-up products (Yoga Mat, Coffee Maker, Smart Watch,
  Wireless Earbuds), generated by `data/make_reviews.py` from sentence templates. They are not copied from any website,
  and they contain no personal data. After removing empty and duplicate rows, 392 are used.
- **Evaluation sets:** also synthetic review texts. The labels were made as described in [EVALUATION.md](EVALUATION.md).
- **Uploaded files** are kept in memory only, for as long as the server runs. They are never saved to disk or sent anywhere.
- Libraries used: FastAPI, pandas, vaderSentiment (MIT), Three.js (MIT).

## Cost

**£0.** Everything runs on free, open-source tools on a CPU: no paid API, no GPU, no database.
It is hosted on Render's free tier. Analysing all 392 reviews takes well under a second.

## Limitations

- **Keyword-based aspects:** wording that is not in the list is missed. This mostly affects quality (recall 0.32 on the sealed set).
- **VADER reads words, not meaning:** sarcasm ("Oh great, another charger that dies"), "problem solved" and neutral facts are often scored wrongly. Neutral is the weakest mood.
- **One mood per sentence:** a sentence that praises one thing and criticises another gets one score.
- **English only.**
- **Synthetic data:** real reviews are messier, so real-world scores would likely be lower.
- **Small evaluation sets:** 49 labels, so one mistake moves recall by about 2 points.
- **One shared dataset:** an upload replaces the data for everyone using the site until the server restarts. That's fine for a demo, but it's not multi-user.
- **The Q&A grouping is not scored:** only aspect detection and mood are measured. The answers were checked by hand.
